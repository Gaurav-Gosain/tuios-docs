tuios (Terminal UI Operating System) gives each shell its own window. You can put windows side by side, move between them, and close the terminal without losing them. The steps below take about five minutes.

## First steps

<Steps>

<Step>

### Install tuios

<Tabs items={['Homebrew', 'Arch (AUR)', 'Script', 'Go']}>
<Tab value="Homebrew">
```bash
brew install tuios
```
</Tab>
<Tab value="Arch (AUR)">
```bash
yay -S tuios-bin
```
</Tab>
<Tab value="Script">
```bash
curl -fsSL https://raw.githubusercontent.com/Gaurav-Gosain/tuios/main/install.sh | bash
```
</Tab>
<Tab value="Go">
```bash
go install github.com/Gaurav-Gosain/tuios/cmd/tuios@latest
```
</Tab>
</Tabs>

Check the install:

```bash
tuios --version
```

The first line shows the version, for example `tuios version 0.13.3 [pure-Go backend]`. [Getting Started](/docs/getting-started#install) has more ways to install.

</Step>

<Step>

### Start tuios

Type `tuios` in your terminal and press <kbd>Enter</kbd>. The welcome screen opens.

<Shot
  name="first-start"
  light
  framed
  width={2038}
  height={1340}
  alt="The tuios welcome screen. It shows the keys n for a new window, N for a new session, ? for help and , for settings."
/>

</Step>

<Step>

### Open a window

Press <kbd>n</kbd>. A window opens with your shell in it. Press <kbd>i</kbd> to type in the window, then type a command such as `ls`.

<Shot
  name="first-window"
  light
  framed
  width={2038}
  height={1340}
  alt="One tuios window that fills the screen. The ls command shows the files of the project folder. The list on the right shows the same files."
/>

</Step>

<Step>

### Split the window

Press <kbd>Ctrl</kbd>+<kbd>B</kbd>, release both keys, then press <kbd>|</kbd>. A second window opens beside the first one. You type in the new window.

<Shot
  name="first-split"
  light
  framed
  width={2038}
  height={1340}
  alt="Two tuios windows side by side. The left window shows the ls output. The right window shows the text of README.md."
/>

Click a window to type in it. <kbd>Ctrl</kbd>+<kbd>B</kbd> then <kbd>-</kbd> opens the new window below.

</Step>

<Step>

### Quit

Press <kbd>Ctrl</kbd>+<kbd>B</kbd>, then <kbd>q</kbd>. The quit menu opens.

<Shot
  name="first-quit"
  light
  framed
  width={2038}
  height={1340}
  alt="The quit menu of tuios over the two windows. It has two items: Detach, and Kill and quit."
/>

- Press <kbd>d</kbd> to detach. tuios closes, and your windows continue to run. Type `tuios` again to go back to them.
- Press <kbd>x</kbd> to kill the session and quit. tuios stops the programs in all windows.

</Step>

</Steps>

## What you get

**Windows and layout**

- Two modes, modelled on vim: window management mode for arranging windows, terminal mode for typing into one.
- BSP tiling by default, with explicit splits, preselection, swapping and resizing. Master-stack and a niri-style scrolling layout are one palette command away.
- Nine workspaces, zoom, minimize, layout templates and optional shared borders.
- A session rail on the right lists your sessions, panes, files and agents.
- A command palette (<kbd>Ctrl</kbd>+<kbd>P</kbd>) and an app launcher (<kbd>Alt</kbd>+<kbd>Space</kbd>).

**Sessions**

- A daemon owns the shells, so detaching costs nothing and several terminals can attach to one session at once.
- Window layout, working directories and each pane's history come back after a daemon restart or a reboot. A live upgrade to a new build (`tuios daemon upgrade`) keeps the running programs too. See [Sessions](/docs/sessions) and [Restarting the Daemon](/docs/daemon-restart).
- Sessions and single panes can live on other machines, reached over ssh. `tuios hosts setup` links a machine in one command, and `tuios cp` copies files between them. See [Remote Hosts](/docs/remote-hosts).

**Scripting**

- A JSON [control protocol](/docs/control-protocol) on the daemon socket, with blocking waits and an event stream.
- CLI commands for the same things: `send-text`, `capture-pane`, `wait-for`, `new-window` and more.
- [Tape scripts](/docs/tape-scripting) to record and replay workflows, and [hooks](/docs/hooks) that run shell commands on window, session and agent events.

**Agents**

- Panes that run coding agents report whether the agent is working, idle or waiting for you. See [Agents](/docs/agents).
- One [Inbox](/docs/agent-inbox) lists every approval, question and finished turn waiting for you, in every session, and answers them from where you are.
- Review what an agent changed, leave notes on its lines, and send them back. Fan one prompt out to several agents in git worktrees and keep the best result.
- [Task boards](/docs/task-boards) hand out work as cards, and dispatch can give the next card to a free agent or start an agent for each card.
- An agent can hand a task to a child agent with `tuios delegate` and get the answer back by mail. See [Agent Messaging](/docs/agent-messaging).

**Terminal**

- Vim-style copy mode over 10,000 lines of scrollback per window, plus mouse wheel scrolling and selection.
- [Multi copy mode](/docs/layout-modes#multi-copy-mode) searches every pane of the multifocus set at once and copies the selection of each pane.
- [Hints](/docs/hints) put a label on each URL, path and hash in a pane. Type the label to copy the text.
- Kitty graphics (including `mpv --vo=kitty` video), sixel images cropped to their window, the kitty keyboard protocol and synchronized output.
- 345 built-in themes with a live picker, an in-app settings page, and an [Option Explorer](/docs/config-options) for every option.

**Remote access**

- `tuios ssh` serves TUIOS over SSH with public key authentication.
- `tuios-web`, a separate binary, serves it to a browser. See [Web Terminal](/docs/web).
