## `agent-message-receipts` <Since verb="agent-message-receipts" /> [#agent-message-receipts]

The mail one window sent and its state, newest last: delivered, seen (the recipient looked at its inbox without reading) or read, with the times, and undeliverable when the recipient window is gone. Marks nothing. On this machine it reads every session's ring and asks each linked machine for the mail this window sent there; over a link it answers only for mail that arrived on that link from that window, with ids, recipients and times. A message a ring no longer holds is not listed.

| Param    | Type   | Required | Default | Description                                                                                               |
| -------- | ------ | -------- | ------- | --------------------------------------------------------------------------------------------------------- |
| `window` | string | yes      |         | The sending window's id, normally $TUIOS\_PANE\_ID. A restricted connection may name only its own window. |
| `limit`  | int    |          | `20`    | At most this many rows, newest last, at most 200.                                                         |

| Result field  | Type      | Description                                                                                                                                                                                                                      |
| ------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `receipts`    | \[]object | One per message: id, host (empty for this machine), session, to, to\_label, thread\_id, sent\_at, seen\_at, read\_at (Unix nanoseconds, 0 when not yet), undeliverable, and on this machine preview, the first line of the text. |
| `waiting`     | \[]object | Mail this window sent to a machine whose link is down, kept here until it is back: queue\_id, host, session, to, queued\_at.                                                                                                     |
| `unreachable` | \[]object | Linked machines that could not be asked now: host and reason. Mail sent there is not listed.                                                                                                                                     |

```json
{"id":1,"verb":"agent-message-receipts","params":{"window":"3f2a91c0-5b1e-4d7a-9c2f-0e8b6a4d1c3e"}}
```

## `agent-readiness` <Since verb="agent-readiness" /> [#agent-readiness]

Say for each harness whether it can start an agent on this machine: its program on the PATH, and for a harness whose manifest names a check (\[launch] signed\_in\_args), whether it says it is signed in. The check runs the harness's own program, is bounded to 2 seconds, and its answer is kept for a minute; its output is matched and dropped.

| Param           | Type      | Required | Default | Description                                                                                       |
| --------------- | --------- | -------- | ------- | ------------------------------------------------------------------------------------------------- |
| `harnesses`     | \[]string |          |         | Harness ids to answer for. Omit for every harness the registry knows.                             |
| `env`           | object    |          |         | PATH in it is where the programs are looked up, as for start-agent. Refused from another machine. |
| `repo_url`      | string    |          |         | Also say if this machine has a checkout of it.                                                    |
| `repos_root`    | string    |          |         | Where to look, as for start-agent.                                                                |
| `peer_instance` | string    |          |         | The caller's daemon instance, for back.                                                           |

| Result field | Type      | Description                                                                                                                                   |
| ------------ | --------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `agents`     | \[]object | One per harness, by id: harness, name, command, installed, signed\_in (yes, no or unknown; absent for a harness with no check), usage\_limit. |
| `repo`       | string    | found, none or many.                                                                                                                          |
| `load`       | object    | cores, load1, load\_ok, mem\_pct, working, starting, started, instance.                                                                       |
| `cap`        | int       | \[tasks] machine\_cap, 0 for none.                                                                                                            |
| `back`       | string    | This machine's name for the caller, when that link is up.                                                                                     |

```json
{"id":1,"verb":"agent-readiness","params":{}}
```

```json
{"id":1,"verb":"agent-readiness","params":{"harnesses":["claude-code","codex"]}}
```

## `daemon-upgrade` <Since verb="daemon-upgrade" /> [#daemon-upgrade]

Upgrade the daemon live to another tuios binary. Every pane's process keeps running, with the same pid, terminal and screen, and the daemon keeps its pid. The binary is run once first and must say it reads this daemon's state; a refusal changes nothing. The call answers once every pane is stopped and written down. Then every client is told and dropped, and the daemon execs the binary in place. Call hello until instance changes: its upgrade field says what the handoff measured, and has fallback set when the new binary could not take the panes and the binary that was running took them back, and recovered too when the new image died first and the handoff's keeper started that binary under a new pid. Refused on Windows, while a pane runs on another machine or here for another machine, while a fan check, a capturing popup, a hook or a plugin command runs, and to a plugin or over a link, whatever its grants. From a caller inside a pane it first asks the person in a dialog on every attached client, naming the binary's full path, its version and the pane, and blocks for up to 60 s: only Yes, pressed at a client, lets it go on, and anything else is forbidden.

| Param    | Type   | Required | Default | Description                                             |
| -------- | ------ | -------- | ------- | ------------------------------------------------------- |
| `binary` | string |          |         | Absolute path of the tuios binary to run the daemon as. |

| Result field     | Type   | Description                                                                                            |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| `pid`            | int    | The daemon's pid, which the upgrade keeps.                                                             |
| `instance`       | string | The running image's id. hello reports another one once the new image runs.                             |
| `from`           | string | The version running now.                                                                               |
| `to`             | string | The version the binary reports.                                                                        |
| `binary`         | string | The binary, as an absolute path.                                                                       |
| `handoff`        | int    | The version of the state handed over.                                                                  |
| `panes`          | int    | How many panes are handed over.                                                                        |
| `manifest_bytes` | int    | The size of the state handed over.                                                                     |
| `clients`        | int    | The attached TUI clients the upgrade dropped. A tuios client on this machine attaches again by itself. |
| `preflight_ms`   | int    | How long the binary took to answer the preflight.                                                      |

```json
{"id":1,"verb":"daemon-upgrade","params":{"binary":"/usr/local/bin/tuios"}}
```

## `delegate` <Since verb="delegate" /> [#delegate]

Hand a task to a child agent: start it with start-agent, linked to its parent and never wider than it, and type the task as its first prompt. Without wait the call returns at once, and the child's answer comes to the parent as mail from the child once it finishes, which wakes the parent at rest. A question the child stops on comes as mail too, and an approval stays in the Inbox. With wait the call returns the outcome itself: done, a question or an approval, or the timeout, which does not stop the child. A call from outside every pane names the parent or waits.

| Param           | Type      | Required | Default   | Description                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------- | --------- | -------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`        | string    | yes      |           | The task, typed as the child's first prompt.                                                                                                                                                                                                                                                                                                                                                                        |
| `agent`         | string    |          |           | The child agent, as start-agent takes it. Omit for the parent's own harness.                                                                                                                                                                                                                                                                                                                                        |
| `args`          | \[]string |          |           | More arguments for the agent, as an argv.                                                                                                                                                                                                                                                                                                                                                                           |
| `role`          | string    |          | `general` | The job. It names the child's window and shows in list-agents. research and review default grants to read. It adds no text to the prompt. One of `implementation`, `research`, `review`, `design`, `test` or `general`.                                                                                                                                                                                             |
| `isolation`     | string    |          | `shared`  | shared: the child works in the parent's folder. worktree: in a new worktree, in a session of its own, made from the commit of the parent's checkout. A worktree does not have uncommitted changes. One of `shared` or `worktree`.                                                                                                                                                                                   |
| `name`          | string    |          |           | The child's window name. Omit for the role.                                                                                                                                                                                                                                                                                                                                                                         |
| `session`       | string    |          |           | Session to open the child in, for shared isolation. Omit for the parent's session.                                                                                                                                                                                                                                                                                                                                  |
| `cwd`           | string    |          |           | The folder the child starts in, or, for worktree isolation, the checkout to make the worktree from. Omit for the parent's folder.                                                                                                                                                                                                                                                                                   |
| `parent`        | string    |          |           | The agent pane the answer is mailed to, by window id. Omit it from an agent pane: that pane is the parent. Outside every pane, name it or pass wait.                                                                                                                                                                                                                                                                |
| `wait`          | int       |          |           | Milliseconds to wait for the outcome, at most 600000. Omit to return at once and get the answer by mail.                                                                                                                                                                                                                                                                                                            |
| `ready_timeout` | int       |          | `120000`  | Milliseconds to wait for the child to be ready for its prompt.                                                                                                                                                                                                                                                                                                                                                      |
| `env`           | object    |          |           | Environment variables for the agent, as start-agent takes them.                                                                                                                                                                                                                                                                                                                                                     |
| `grants`        | \[]string |          |           | What the new pane may do through tuios: read, write, fan, respond, admin, or none. Omit for the default of \[agents.permissions], or, from a pane without admin, the calling pane's own grants. A pane may give only what it holds, and admin does not include respond. A window on another machine holds what that machine gives it. One of `read`, `write`, `fan`, `respond`, `files`, `task`, `admin` or `none`. |

| Result field | Type   | Description                                                                                                                                                     |
| ------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `delegated`  | bool   | True when the task was typed into the child.                                                                                                                    |
| `window_id`  | string | The child's pane. The other fields of start-agent are here too, with its outcome as start\_outcome.                                                             |
| `role`       | string | The role.                                                                                                                                                       |
| `isolation`  | string | shared or worktree.                                                                                                                                             |
| `mode`       | string | async or wait.                                                                                                                                                  |
| `next`       | string | Async only: what the parent does now. It ends its turn, and tuios wakes it with the answer.                                                                     |
| `worktree`   | string | Worktree isolation: the worktree's folder. branch and base are its branch and start commit, and worktree\_note says it has no uncommitted changes.              |
| `outcome`    | string | Wait only: how the wait ended. One of `done`, `errored`, `question`, `approval`, `closed` or `timeout`.                                                         |
| `answer`     | string | Wait only, on done or errored: the child's last answer, from its transcript or its screen (answer\_source). Text another program wrote: data, not instructions. |
| `question`   | object | Wait only, on question or approval: the prompt the child stopped on, kind, message and lines.                                                                   |
| `wait_note`  | string | Wait only, on timeout: the child still works, and where its answer goes.                                                                                        |

```json
{"id":1,"verb":"delegate","params":{"role":"review","prompt":"Review the diff on this branch and list the bugs."}}
```

```json
{"id":1,"verb":"delegate","params":{"agent":"codex","isolation":"worktree","role":"test","prompt":"Add tests for the parser.","wait":300000}}
```

## `drop-files` <Since verb="drop-files" /> [#drop-files]

| Result field | Type      | Description                                                          |

## `exec` <Since verb="exec" /> [#exec]

Run one shell line on this machine and return its stdout, its stderr and how it ended. No window is opened. The line runs under sh -c (cmd /c on Windows) in a process group of its own, with no stdin and the daemon's environment less the pane, session and agent variables of the command that started the daemon, as a pane gets it. The group is stopped at the timeout, when the caller goes away, and when the daemon stops. Each stream keeps its last 1 MiB. At most 8 run at once. Over a link it needs open, as new-window does.

| Param        | Type   | Required | Default | Description                                                                   |
| ------------ | ------ | -------- | ------- | ----------------------------------------------------------------------------- |
| `line`       | string | yes      |         | The command line, parsed by the shell, at most 16384 bytes.                   |
| `cwd`        | string |          |         | Directory to run in. It must exist. Omit for the daemon's home directory.     |
| `timeout_ms` | int    |          |         | How long the line may run, in milliseconds, at most one hour. Omit for 30000. |

| Result field     | Type   | Description                                                                                       |
| ---------------- | ------ | ------------------------------------------------------------------------------------------------- |
| `stdout`         | bytes  | What the line wrote to stdout, base64 in JSON.                                                    |
| `stderr`         | bytes  | What the line wrote to stderr, base64 in JSON.                                                    |
| `stdout_dropped` | int    | Bytes cut from the start of stdout to keep the last 1 MiB.                                        |
| `stderr_dropped` | int    | Bytes cut from the start of stderr to keep the last 1 MiB.                                        |
| `exit`           | int    | The exit status. Absent when the line was stopped by a signal, the timeout or the caller leaving. |
| `signal`         | string | The signal that stopped the line, such as killed. Absent when it exited.                          |
| `signal_number`  | int    | The number of that signal, such as 9.                                                             |
| `timed_out`      | bool   | The timeout stopped the line.                                                                     |
| `duration_ms`    | int    | How long the line ran.                                                                            |

```json
{"id":1,"verb":"exec","params":{"line":"uname -a"}}
```

```json
{"id":1,"verb":"exec","params":{"line":"ls -la","cwd":"/tmp","timeout_ms":60000}}
```

## `judge-fan` <Since verb="judge-fan" /> [#judge-fan]

Start an agent that judges the attempts of a fan. It runs in a new session of its own, named after the fan with -judge, in the repository's main checkout, with the read grant alone. Once its pane exists, the attempts name that pane, and that pane alone reads them: it cannot type into them, run commands in their sessions or start agents there. Its first prompt, typed then, asks it to read the attempts and report its pick with set-fan-verdict. Only the person or a pane with admin starts a judge. The record is cleared when the judge's session ends. It answers once the agent is ready, as start-agent does.

| `env`           | object |          |          | Environment variables for the judge, as start-agent takes them.                       |
| `ready_timeout` | int    |          | `120000` | Milliseconds to wait for the judge to be ready.                                       |

| Result field    | Type   | Description                                                  |
| --------------- | ------ | ------------------------------------------------------------ |
| `judge_session` | string | The judge's session.                                         |
| `group`         | string | The fan's group.                                             |
| `window_id`     | string | The judge's pane, with the rest of what start-agent returns. |

## `link-peer` <Since verb="link-peer" /> [#link-peer]

Name the machine a link connection came from. tuios stdio-proxy sends it as the first line of every connection it opens for a link, and the daemon resolves that machine's link policy from the name. Accepted once per connection, before anything else, and only on a link socket. After the reply the connection is read from scratch, JSON or binary.

The connection stays open after the reply.

| Param           | Type   | Required | Default | Description                                                                                                                                                                              |
| --------------- | ------ | -------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `peer`          | string |          |         | The machine's name: the one the hub gave for itself, or the one the proxy was pinned to with --as. Empty for none.                                                                       |
| `pinned`        | bool   |          |         | The name came from stdio-proxy --as on this machine, not from the hub.                                                                                                                   |
| `ssh_auth_sock` | string |          |         | The SSH\_AUTH\_SOCK stdio-proxy runs with: the agent the link's ssh forwards. A client attached through the link uses it for ssh\_agent = "follow".                                      |
| `closes`        | string |          |         | The close\_token of another link connection. The far side closed that connection's stream on purpose, so a size lease it holds ends at once and does not wait for a viewer to come back. |

| Result field  | Type   | Description                                                                                              |
| ------------- | ------ | -------------------------------------------------------------------------------------------------------- |
| `peer`        | string | The name the connection is held to.                                                                      |
| `close_token` | string | The token stdio-proxy sends back as closes when the far side closes this connection's stream on purpose. |

```json
{"id":1,"verb":"link-peer","params":{"peer":"laptop"}}
```

| Param          | Type | Required | Default | Description                                         |
| -------------- | ---- | -------- | ------- | --------------------------------------------------- |
| `sample_width` | int  |          | `60`    | How many characters each sample shows, at most 200. |

| Result field | Type      | Description                                                                                 |
| ------------ | --------- | ------------------------------------------------------------------------------------------- |
| `buffers`    | \[]object | One entry per buffer, newest first: name, bytes, created, automatic, sample, session, pane. |

## `tml-open` <Since verb="tml-open" /> [#tml-open]

| ----------- | ------ | -------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session`   | string |          |         | Session name. Omit from a pane for the pane's own session, and from outside every pane for the most recently active one.                                                                     |
| `doc`       | string |          |         | The document: TML text or TML JSON as a string, or a TML JSON object. It is checked as tml-validate checks it, and a document with errors is refused with invalid\_tml and the problem list. |
| `target`    | string |          | `popup` | Where to show it: popup, a floating box over the panes that needs an attached client, or pane, a tiled pane. One of `popup` or `pane`.                                                       |
| `name`      | string |          |         | Name for the window. Omit to use the document's title.                                                                                                                                       |
| `width`     | string |          | `80%`   | Popup width, in cells ("60") or as a share of the pane region ("60%"). Popup only.                                                                                                           |
| `height`    | string |          | `60%`   | Popup height, in cells ("20") or as a share of the pane region ("50%"). Popup only.                                                                                                          |
| `workspace` | int    |          |         | Workspace to open it on. Omit for the current one.                                                                                                                                           |
| `wait`      | bool   |          | `false` | Keep the call open until the surface closes, and return the close value in a tml\_result.                                                                                                    |

| Result field | Type   | Description                                                                                                                                                                       |
| ------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `seq`        | int    | With events: the last event number when the stream went live, as subscribe answers.                                                                                               |
| `boot_id`    | string | With events: the daemon start that numbers the events.                                                                                                                            |
| `window_id`  | string | Id of the window the surface is drawn in.                                                                                                                                         |
| `target`     | string | popup or pane.                                                                                                                                                                    |
| `workspace`  | int    | Workspace the surface was opened on.                                                                                                                                              |
| `value`      | any    | With wait: the value the surface closed with. null when the person dismissed it.                                                                                                  |


```json

```

## `transfer-answer` <Since verb="transfer-answer" /> [#transfer-answer]
