TUIOS has two modes. **Window mode** is for managing panes. **Terminal mode** sends your keys to the focused pane. A new session starts in window mode.

The leader key is <kbd>Ctrl</kbd>+<kbd>B</kbd>. Press it, release it, then press a command key. The leader works in both modes.

Every table on this page names the config section that holds the binding and the action name to use in it. Every action is rebindable. See [Customizing](#customizing) at the end.

**Try it live:** [Learn tuios](/learn) has you press these keys in the real app, in your browser. [Free play](/learn?t=play) has a cheat sheet you can click.

<Callout type="info" title="Check your own bindings">
This page lists the defaults. `tuios keybinds list`, `tuios keybinds explain <key>` and the keybind manager (<kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>k</kbd>) show what is bound on your machine.
</Callout>

## Modes

Section: `[keybindings.mode_control]`. These keys work in window mode.

| Key | Action | Does |
|-----|--------|------|
| <kbd>i</kbd>, <kbd>Enter</kbd> | `enter_terminal_mode` | Enter terminal mode |
| <kbd>Esc</kbd> | `enter_window_mode` | Enter window mode |
| <kbd>?</kbd> | `toggle_help` | Toggle the help overlay |
| <kbd>,</kbd> | `open_settings` | Open the settings page |
| <kbd>q</kbd> | `quit` | Quit. In a daemon session it opens the quit menu |
| none | `hold_window_mode` | Window mode while the key is held. Unbound by default |

To leave terminal mode, press <kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>Esc</kbd>, or the direct key from [Terminal mode](#terminal-mode).

`hold_window_mode` needs a terminal that speaks the Kitty keyboard protocol (Ghostty, kitty, WezTerm, foot, Alacritty), because only that protocol reports key releases. Bind it to an ordinary spare key, such as an unused function key from `f1` to `f12`. Binding a modifier such as `leftalt` also works, but then every keystroke in the session arrives as an escape code.

<Callout type="warn" title="Alt+Left and Alt+Right cost you word motions">
Readline, fish and zsh use <kbd>Alt</kbd>+<kbd>←</kbd> and <kbd>Alt</kbd>+<kbd>→</kbd> to move a word at a time. To give them back, run `tuios keybinds free alt+left` and `tuios keybinds free alt+right`. <kbd>Ctrl</kbd>+<kbd>B</kbd> then an arrow still moves focus.
</Callout>

Plain <kbd>Ctrl</kbd>+<kbd>V</kbd> is not bound. It reaches the pane, so vim's visual block mode works.

## Global keys

Section: `[keybindings.global]`. These keys work in window mode and terminal mode.

| Key | Action | Does |
|-----|--------|------|
| <kbd>Ctrl</kbd>+<kbd>P</kbd> | `command_palette` | Open the command palette |
| <kbd>Alt</kbd>+<kbd>Space</kbd> | `launcher` | Open the app launcher |

The **command palette** searches commands, sessions and windows. Start the query with `@` to filter panes by agent state (`@n` for needs input), or with `#` to search actions to rebind.

The **app launcher** lists every executable on `$PATH`, ranked by use. <kbd>Enter</kbd> runs the selection in a new pane with no shell in between. <kbd>Tab</kbd> types the command into the focused shell instead, so you can add arguments.

These two keys take <kbd>Ctrl</kbd>+<kbd>P</kbd> from fish and vim and <kbd>Alt</kbd>+<kbd>Space</kbd> from readline. Set an action to `[]` to give its key back. On macOS, <kbd>Option</kbd>+<kbd>Space</kbd> types a non-breaking space, so use <kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>a</kbd> for the launcher.

| <kbd>p</kbd> | `file_paste` | Paste into this folder |

See [The files section](/docs/configuration#the-files-section).

When the cursor is on an agent row, section `[keybindings.sidebar_agents]` answers first. So <kbd>r</kbd> and <kbd>x</kbd> act on the agent there, and keep their rail meaning on every other row:

| Key | Action | Does |
|-----|--------|------|
| <kbd>r</kbd> | `agent_reply` | Reply to the agent. The message is queued and typed when the agent is at rest |
| <kbd>v</kbd> | `agent_review` | Review the pane's changes |
| <kbd>u</kbd> | `agent_unread` | Mark the pane's finished turn unread again, for every client |
| <kbd>z</kbd> | `agent_snooze` | Open the Inbox on the pane's item, ready to snooze it |
| <kbd>x</kbd> | `agent_cancel_queued` | Drop the newest queued message. <kbd>u</kbd> within 10 seconds queues it again. With nothing queued, <kbd>x</kbd> opens the row's menu as usual |

<kbd>Enter</kbd> on the `+N at rest` line shows the agent rows folded there.

## Inbox and mailbox

The [Inbox](/docs/agent-inbox) lists everything waiting for you in every session. Open it with <kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>i</kbd>. Its keys are in `[keybindings.inbox]`:

| Key | Action | Does |
|-----|--------|------|
| <kbd>j</kbd>, <kbd>↓</kbd>, <kbd>Ctrl</kbd>+<kbd>N</kbd> | `inbox_down` | Move down |
| <kbd>k</kbd>, <kbd>↑</kbd>, <kbd>Ctrl</kbd>+<kbd>P</kbd> | `inbox_up` | Move up |
| <kbd>PgDn</kbd>, <kbd>PgUp</kbd> | `inbox_page_down`, `inbox_page_up` | Move a page |
| <kbd>g</kbd>, <kbd>Home</kbd> / <kbd>G</kbd>, <kbd>End</kbd> | `inbox_first`, `inbox_last` | First or last item |
| <kbd>Enter</kbd> | `inbox_go` | Go to the item's pane, or open a mail thread |
| <kbd>Space</kbd> | `inbox_peek` | Read an approval's or a question's prompt and answer it from the Inbox |
| <kbd>d</kbd>, <kbd>Delete</kbd> | `inbox_dismiss` | Dismiss the item. <kbd>u</kbd> undoes it for 10 seconds |
| <kbd>r</kbd> | `inbox_reply` | Reply to mail, or to the agent of a finished or errored item |
| <kbd>y</kbd> | `inbox_resume` | On a resume row, type the conversation's resume command in its pane |
| <kbd>p</kbd> | `inbox_pass_on` | Pass on mail held from another machine |
| <kbd>f</kbd> | `inbox_filter` | Show one kind, then the next, then all |
| <kbd>/</kbd> | `inbox_select` | Narrow the list with a selector, such as `harness:codex needs:you` |
| <kbd>m</kbd> | `inbox_mailbox` | Open the mailbox |
| <kbd>v</kbd> | `inbox_review` | Review the changes in the item's pane |
| <kbd>z</kbd> | `inbox_snooze` | Snooze the item: then <kbd>1</kbd> 15 minutes, <kbd>2</kbd> an hour, <kbd>3</kbd> until 9:00 tomorrow, <kbd>4</kbd> until it changes. On a snoozed item, wake it |
| <kbd>u</kbd> | `inbox_undo` | Undo the last dismiss or snooze, within 10 seconds |
| <kbd>S</kbd> | `inbox_show_snoozed` | Show or hide the snoozed items |
| <kbd>n</kbd> | `inbox_deny_reason` | Deny a held approval, or keep a plan planning, with a reason you type |
| <kbd>J</kbd>, <kbd>Ctrl</kbd>+<kbd>D</kbd> / <kbd>K</kbd>, <kbd>Ctrl</kbd>+<kbd>U</kbd> | `inbox_detail_down`, `inbox_detail_up` | Scroll the detail under the list, such as a long plan |
| <kbd>Esc</kbd>, <kbd>q</kbd> | `inbox_close` | Close |

On an approval the Inbox holds for you, <kbd>1</kbd> allows it once, <kbd>2</kbd> always allows it and <kbd>3</kbd> denies it. On a question put with `ask-human`, a digit picks that answer. The digits are not bindings.

The prompt that <kbd>Space</kbd> opens has its own section, `[keybindings.inbox_peek]`:

| Key | Action | Does |
|-----|--------|------|
| <kbd>a</kbd> | `peek_approve` | Approve |
| <kbd>A</kbd> | `peek_approve_always` | Approve and do not ask again, when the menu offers it |
| <kbd>d</kbd> | `peek_deny` | Deny |
| <kbd>Tab</kbd> | `peek_type` | Type an answer |
| <kbd>r</kbd> | `peek_read_again` | Read the prompt again |
| <kbd>Enter</kbd> | `peek_go` | Go to the pane instead |
| <kbd>Esc</kbd>, <kbd>q</kbd>, <kbd>Space</kbd> | `peek_back` | Back to the list |

A digit chooses that numbered option of the prompt.

The mailbox (<kbd>m</kbd> in the Inbox) uses `[keybindings.mail]`: <kbd>j</kbd>/<kbd>k</kbd> (`mail_down`, `mail_up`), <kbd>PgDn</kbd>/<kbd>PgUp</kbd> (`mail_page_down`, `mail_page_up`), <kbd>Enter</kbd> opens a thread (`mail_open`), <kbd>r</kbd> replies (`mail_reply`), <kbd>o</kbd> goes to the pane (`mail_focus_pane`) and <kbd>Esc</kbd> or <kbd>q</kbd> goes back (`mail_back`).

The footers name whatever key your config binds. Until an agent has been seen, the prefix menu, the help and the palette leave out the agent keys and entries, so a person who runs no agents is not shown them. The keys work before that too, except <kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>O</kbd>, which types <kbd>O</kbd> into the pane until then.

## The review overlay

<kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>v</kbd>, or <kbd>v</kbd> in the Inbox or on a rail agent row, opens the diff of a pane's changes over the whole screen. See [Reviewing an agent's changes](/docs/agent-inbox#reviewing-an-agents-changes). These keys are fixed and are not in the config.

| Keys | Does |
|------|------|
| <kbd>j</kbd> <kbd>k</kbd>, arrows | Move by line. With the file list focused, move through the files |
| <kbd>Space</kbd>, <kbd>PgDn</kbd>, <kbd>Ctrl</kbd>+<kbd>D</kbd> / <kbd>PgUp</kbd>, <kbd>Ctrl</kbd>+<kbd>U</kbd> | Move a page |
| <kbd>g</kbd> <kbd>G</kbd> | First or last line |
| <kbd>]</kbd> <kbd>[</kbd> | Next or previous hunk, going on into the next or previous file |
| <kbd>&#125;</kbd> <kbd>&#123;</kbd> | Next or previous file |
| <kbd>s</kbd> | One column, or old and new side by side when the screen is wide enough |
| <kbd>h</kbd> <kbd>l</kbd>, <kbd>←</kbd> <kbd>→</kbd> | Scroll the code sideways |
| <kbd>Tab</kbd> | Focus the file list or the diff |
| <kbd>Enter</kbd> | In the file list, open that file |
| <kbd>c</kbd> / <kbd>C</kbd> | A note on the line under the cursor, or on the whole hunk |
| <kbd>e</kbd> | Edit the note under the cursor |
| <kbd>x</kbd> | Resolve (remove) the note under the cursor |
| <kbd>S</kbd> | Send every unsent note to the agent as one message, typed when it is at rest |
| <kbd>u</kbd> | Switch between the changes since the base and only the uncommitted ones |
| <kbd>b</kbd> | Diff from another base |
| <kbd>w</kbd> | The compare view, for a pane in a fan |
| <kbd>r</kbd> | Read the diff again |
| <kbd>Esc</kbd>, <kbd>q</kbd> | Close |

The compare view lists the attempts of a fan. <kbd>j</kbd>/<kbd>k</kbd> move, <kbd>Enter</kbd> reviews an attempt, <kbd>m</kbd> marks one and <kbd>d</kbd> diffs the two marked attempts, <kbd>V</kbd> runs a command in every attempt, <kbd>K</kbd> keeps the attempt under the cursor and removes the others after a <kbd>y</kbd>, and <kbd>Esc</kbd>, <kbd>q</kbd> or <kbd>w</kbd> go back to the review.

| Gesture | Does |
|---------|------|
| Click a pane | Focus it |
| Double-click a pane | In window mode, also start typing in it. `appearance.click_to_type` makes it a single click, or turns it off |
| Drag a title bar | Move the window. In tiling, swap it with the pane you drop it on |

## Customizing

Bindings live in 23 sections under `[keybindings]` in `config.toml`. Each action takes a list of keys.

```toml
[keybindings]
leader_key = "ctrl+a"

[keybindings.window_management]
new_window = ["n", "ctrl+t"]
close_window = []          # unbind: the key goes back to the pane
```

An empty list and a missing line are different. A missing action gets its default back at the next load. An empty list stays empty. Key syntax and every section are on the [Configuration](/docs/configuration#keybindings) page.

Inspect and change bindings from the shell:

```bash
tuios keybinds list                       # the main tables
tuios keybinds doctor                     # conflicts, and keys taken from the pane
tuios keybinds explain alt+left           # everything one key does
tuios keybinds unbind close_window w      # take one key off one action
tuios keybinds free alt+left              # take a key off every action
```

`doctor` tags each finding with its evidence: `certain` comes from TUIOS routing, `observed` from the live pane, `reference` from a list of common program defaults. `doctor` and `explain` take `--json` and `--guest <program>`.

The **keybind manager** (<kbd>Ctrl</kbd>+<kbd>B</kbd> <kbd>k</kbd>) shows the same analysis in four tabs: Bindings, Conflicts, Guests and Record. Record captures the next key you press. On a binding, <kbd>Ctrl</kbd>+<kbd>D</kbd> removes it and <kbd>Ctrl</kbd>+<kbd>X</kbd> takes its key off every action.

<Callout type="warn" title="Keybinding edits need a new client">
The config file reloads on save, but only `leader_key` among the keybindings. After editing other bindings, detach and attach again, or restart TUIOS. Changes made with the keybind manager apply at once.
</Callout>

<Callout type="warn" title="keybinds list-custom is partial">
`tuios keybinds list-custom` compares 9 of the 23 sections: `window_management`, `workspaces`, `layout`, `mode_control`, `system`, `prefix_mode`, `window_prefix`, `minimize_prefix` and `workspace_prefix`. It does not report `leader_key`. Use `tuios keybinds doctor` or read the file for the rest.
</Callout>

## macOS

macOS treats Option as a compose key unless the terminal says otherwise. An Option chord then arrives as a character. TUIOS maps most of those characters back to the chord, which is why <kbd>Option</kbd>+<kbd>1</kbd> to <kbd>Option</kbd>+<kbd>9</kbd> work with no setup. Two kinds cannot be recovered:

- **Dead keys.** <kbd>Option</kbd>+<kbd>e</kbd>, <kbd>i</kbd>, <kbd>n</kbd>, <kbd>u</kbd> and <kbd>&#96;</kbd> send nothing until a second key. <kbd>Alt</kbd>+<kbd>n</kbd> (next window in terminal mode) takes two presses.
- **Rewritten chords.** Many terminals send <kbd>Option</kbd>+<kbd>←</kbd> and <kbd>Option</kbd>+<kbd>→</kbd> as readline word motions, with no sign that an arrow was pressed.

To fix both, turn on your terminal's Option-as-Alt setting:

| Terminal | Setting |
|----------|---------|
| Ghostty | `macos-option-as-alt = true` |
| Terminal.app | Settings > Profiles > Keyboard > Use Option as Meta Key |
| iTerm2 | Settings > Profiles > Keys > Left Option key: Esc+ |
| kitty | `macos_option_as_alt yes` |
| WezTerm | `send_composed_key_when_left_alt_is_pressed = false` |
| Alacritty | `option_as_alt = "Both"` under `[window]` |
| VS Code | `terminal.integrated.macOptionIsMeta` |

Ghostty also needs `keybind = alt+left=unbind` and `keybind = alt+right=unbind`, because its own keybinds rewrite those arrows first.

The prefix works on every terminal with no setup. <kbd>Ctrl</kbd>+<kbd>B</kbd> then an arrow, <kbd>n</kbd>, <kbd>p</kbd>, <kbd>(</kbd>, <kbd>)</kbd>, <kbd>a</kbd> or a digit covers every navigation command.

Command chords never reach a terminal program. macOS sends them to the menu bar.
