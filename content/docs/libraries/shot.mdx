`tuios.dev/shot` renders a terminal screen to a picture. It takes a grid of cells and writes PNG, SVG, HTML, ANSI or plain text, with an optional window frame around it. tuios uses it for [screenshots](/docs/screenshots).

It needs Go 1.25 or later. It is pure Go and needs no cgo, no browser and no external tool. The API reference is on [pkg.go.dev](https://pkg.go.dev/tuios.dev/shot).

## Use it to

- Save a picture of a screen when a terminal test fails.
- Put real terminal output in a README or in docs.
- Post the output of a command from a bot.

## What it does

- **PNG** is drawn in Go. Box drawing, block elements, braille and powerline glyphs are drawn as shapes, so borders join up in any font.
- **SVG** uses real `<text>` and `<rect>` elements. Design tools and browsers open it, and the text stays selectable.
- **HTML** is one file with inline styles. Links stay links.
- **ANSI** and **text** write the screen back as escape sequences or as plain lines.
- **mosaic**, a sub-package, does the opposite: it draws a picture as cells of block glyphs.

## Fonts

PNG looks for each glyph in this order, and the first face that has the glyph draws it:

1. `Frame.Font`, and `Frame.BoldFont` for a bold cell. Without a font, Go Mono.
2. Each face in `Frame.Fallback`, in order.
3. Go Mono, which shot embeds.

A glyph in no face draws as a dotted box. `MissingGlyphs` lists those glyphs before you render, so you can find a font for each one and add it to `Frame.Fallback`.

shot parses a fallback face only when a glyph needs it, and looks up each glyph once per render. A glyph wider than its cell is centred on the cell. tuios fills the fallback list from fontconfig.

SVG and HTML name `Frame.FontFamily` and let the viewer pick the fonts. With `Frame.EmbedFont`, they also carry `Frame.Font` as an `@font-face`.

## Pictures as cells: mosaic

`tuios.dev/shot/mosaic` does the opposite of shot. It draws a picture as cells of block glyphs, each with a foreground and a background colour. tuios uses it for an image when the terminal shows no graphics.

`Sextant` and `Octant` use 2 by 3 and 2 by 4 sub-pixels, for a font that has those glyphs. At 256 colours the cells are dithered. At 16 colours they are always half blocks.

## How do I

- **Save a picture when a terminal test fails?** Keep the vt emulator of the test, then `shot.Render(shot.FormatPNG, shot.FromScreen(term, palette), nil)`.
- **Use my own font?** Set `Frame.Font` and `Frame.BoldFont`, and add faces for missing glyphs to `Frame.Fallback`.
- **Get a picture with no window?** Use `Frame: "none"` in the `FrameSpec`, or a nil frame.
- **Put real output in a README?** Write SVG. Its text stays selectable.
- **Fill a grid from my own screen model?** Use `NewGrid`, and set each cell's text, colours and attributes.

## Where it fits

- tuios uses shot for `tuios screenshot` and the screenshot keys, and mosaic for images on a terminal with no graphics.
- shot reads [vt](/docs/libraries/vt) screens through `FromScreen`.
- The pictures of loom, plot and vt output on these library pages are PNG files from shot.

## Versions

The module is at v0. The API can change between minor versions. `Grid`, `Cell`, `Palette`, `Render`, the five formats and `FromScreen` are settled. The fields of `Frame` and `FrameSpec`, and the `mosaic` package, can still change.

The pictures can change between versions. Do not compare PNG bytes in a test. Compare the grid, or the text and ANSI output.

Its tags have the folder name as a prefix, such as `shot/v0.1.0`. The source is in the [shot folder](https://github.com/Gaurav-Gosain/tuios/tree/main/shot) of the tuios repository, under the MIT licence. The embedded Go Mono fonts are by Bigelow & Holmes, under the Go font licence.
